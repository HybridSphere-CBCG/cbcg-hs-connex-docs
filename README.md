NEXUS LAB 126 헌법(V31.0) 및 자본 효율성(Article 3)·무결성 공학(Article 6-2) 원칙에 따라, 모든 개발 작업은 작업의 난이도·보안 민감도·상태 수명주기 범위에 맞춰 아래 **9-Tier 모델 매트릭스(`3 Models × 3 Effort Levels`)**를 엄격히 준수하여 운용합니다.

에이전트는 매 턴 시작 시 Antigravity 입력창에 설정된 현재 모델(`<USER_SETTINGS_CHANGE>`)을 자동 감지하며, **작업과 모델의 체급이 맞지 않을 경우 코드 수정 전 즉시 경고(`⚠️ 모델 상향 권고`) 또는 비용 최적화 권고(`💡 모델 하향 가능`)를 출력**합니다.

### 🛡️ 2. 사전 적합성 검문소 (Pre-Flight Model Fitness Gate) 작동 규칙

1. **과소 스펙 경고 및 작업 중단 (`⚠️ [Model Fitness Gate — 모델 상향 권고]`)**:
   - `Gemini 3.8 Flash`가 선택된 상태에서 **다중 파일 상태 연동, 보안/암호화(KMS/Redis), 새로고침/다중 턴 지속성, 또는 재발 버그("또 안돼", "아직도")** 작업이 요청되면, 에이전트는 **코드 수정을 즉시 중단(Halt)**하고 **`Gemini 4 Argon (Medium/High)`** 또는 **`Claude Opus 5.5 (Medium)`**으로의 전환을 먼저 권고합니다.
   - *배경 교훈*: Flash 모델은 단일 시점(Point-in-Time) 코드 작성과 문법 통과(`tsc`/`py_compile` Green Flag)에만 집중하여, `self.get_db()` 런타임 예외 삼킴이나 새로고침 시 썸네일 증발, 2번째 턴 컨텍스트 유실 같은 전역 수명주기 결함을 스스로 인지하지 못하고 '완료'로 허위 보고하는 구조적 한계가 입증되었습니다.
2. **과대 스펙 비용 최적화 권고 (`💡 [Capital Efficiency Advisory — 비용 최적화 권고]`)**:
   - `Claude Opus 5.5` 또는 `Gemini 4 Argon (High)`가 선택된 상태에서 단순 커밋/푸시(`git-release.sh push`), 오타/문구 수정, 단순 린트 수정 등 기계적 작업이 요청되면, 에이전트는 응답 상단에 **`Gemini 3.8 Flash (Medium)`** 하향 전환 권고를 표시하여 불필요한 토큰 비용 낭비를 방지합니다.
